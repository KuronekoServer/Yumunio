# 新しいページのテンプレート

サイドバーの「ページを作成」から、白紙またはひな形を選んでページを作成できます。
ページの「下にページを追加」とチームスペース内の追加ボタンにも、同じ選択画面が開きます。

1. 追加先を確認します。自分用のプライベートページ、作成権限のあるチームスペース、管理できる親ページを選べます。
2. テンプレートを選び、本文のプレビューを確認します。名前や説明から検索できます。
3. ページタイトルを必要に応じて変え、「この内容で作成」を押します。

作成前に閉じた場合、ページやDBは増えません。作成後は普通のページとして本文・チェックリスト・表・DBを編集できます。
タイトルを手入力した後は、別のテンプレートを選んでもそのタイトルを保持します。

| テンプレート | 最初に入る内容 |
| --- | --- |
| 白紙のページ | 空の段落 |
| かんばん | 未着手・進行中・完了の3列とサンプルカード、担当者・期限、各行の本文 |
| タスク管理の表 | ステータス・担当者・期限を持つDBとサンプル3行、各行の本文 |
| シンプルな表 | 項目・内容・備考の3列と入力欄。セルへ直接入力し、行・列を追加可能 |
| 議事録 | 日時・参加者、議題、話したこと、決定事項、次のアクション |
| プロジェクト計画 | 目的、範囲、マイルストーン、タスク、懸念、参考情報 |
| 課題報告 | 概要、環境、再現手順、期待・実際の動作、完了条件 |
| タスクチェックリスト | 今日と次にやること、メモ |
| 手順書 | 目的、事前準備、番号付き手順、対処方法、関連情報 |
| 週次レビュー | 目標、進捗、気づき、困っていること、来週のアクション |

用意されたひな形はサーバーの追加設定なしで使えます。画面の表示言語に合わせて日本語または英語の本文を作成します。
作成済みの本文は、表示言語やひな形を後で変更しても書き換わりません。

「個人テンプレートを管理」では、自分が使うページをひな形として保存できます。
保存した個人テンプレートも、新規ページ画面に名前で表示され、選ぶと内容を読み込みます。
この一覧はログイン中のアカウントとワークスペースに限定されます。
個人テンプレートには、保存時に確認した本文だけが入ります。添付、子ページ、DB、共有権限などは引き継ぎません。

どのテンプレートも独立したコピーです。元のひな形や別のコピーを編集しても相互に影響しません。
かんばんとタスク管理の表は、作成ごとに新しいDBをページ配下へ作成し、本文にそのビューを配置します。
DBには表・かんばん・カレンダー・タイムラインの4種類の保存ビューを用意します。本文内DBの上部からも表示を切り替えられます。
日付の表示には「期限」を使います。最初は日付未設定に置かれ、期限を入力すると該当日に表示します。
タイムラインの初期設定では期限を1日分として表示します。開始日・終了日を使う場合は参照元へ日付列を追加し、表示設定で選択してください。
行やカード、日付の項目を開くと、右側の詳細パネルで本文も編集できます。
新規ページ・参照元DB・サンプル行は、1回の保存でまとめて作成します。途中失敗で空のページや未接続のDBを残しません。
シンプルな表は本文の表ブロックで、DBのフィルターやプロパティを必要としない用途向けです。
追加先の親ページ・チームスペースの共有設定は新しいページにも適用されるため、作成前に追加先の説明を確認してください。
DBと行もその階層に従います。ページだけを共有し、子への権限を付けていない場合、ページ本文のDB表示からデータは閲覧できません。

DBの新規行に本文とプロパティの初期値をまとめて適用する場合は、[DBテンプレート](database-templates.md)を使ってください。
本文にDBを配置する方法は[本文内DBと詳細編集](inline-databases.md)を参照してください。

## テンプレートの追加と翻訳

用意されたひな形の構成は `apps/web/public/page-starters.js`、名前・説明・本文は
`apps/web/public/workspace-locales/{ja,en}.json` の `pageTemplates.*` にあります。
IDや利用者の情報を埋め込まず定義します。文章のひな形は通常のテキストブロックとチェックリストを使います。
DB・表を含むひな形は、共有モデル `packages/domain/src/page-starter.js` の構造と、同じ翻訳ファイルの
`pageTemplates.structured.*` の文言から作ります。既存のDBや添付を参照する値はレシピに含められません。
個人テンプレートの保存対象は従来どおり本文のみです。
翻訳の追加・修正は[コミュニティ翻訳](community-translations.md)と同じGitHubの手順です。
`node --test apps/web/test/page-starters.test.js apps/web/test/page-creator.test.js packages/identity/test/content-page-starter.test.js` と `npm run check` で構成・言語間の対応・権限を検証できます。

## 作成APIの補足

同一オリジンのログイン済み画面は `POST /api/content/workspaces/{workspaceId}/pages` へ、
`expectedRevision`・`title`・追加先（`parentId` または `teamspaceId`）とともに
`starter: {type, labels}` を送ります。`type` は `board`・`table`・`simple-table` です。
`labels` の必須項目・長さは共有モデルで固定し、表示言語の文言を送ります。`blocks` と同時指定できません。
DBレシピの `calendarView`・`timelineView` は両方をまとめて指定する追加のラベルです。省略した旧クライアントのレシピと応答照合は、従来の表・かんばんの2ビューで維持します。
既存ページ・DB・添付のIDを受け取らず、構造と新しいIDはサーバーが生成します。
Origin、Cookie、`X-Yumunio-Expected-Account`、現在の追加先権限とリビジョンを検証し、
ワークスペースの保存を1回だけ行います。応答の `starter: {type, ids}` は、生成結果と本文を照合するための情報です。
応答不明時の自動再送は行いません。通常の `blocks` によるページ作成APIは引き続き利用できます。
