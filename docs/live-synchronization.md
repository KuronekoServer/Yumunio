# 自動同期と表示速度

ワークスペースとデータベースの画面は、表示中のワークスペースへ自動接続します。保存された本文、ページ名、ページ一覧、DBの行、リンク済みビュー、同期ブロック、コメント、受信トレイ、バックリンク、添付一覧の変更は、更新ボタンを押さずに取得します。本文はページを開くとYjsの共同編集へ自動接続します。同じアカウントで開いた別の端末も、それぞれ独立した接続・カーソル・Undo履歴として扱います。開始ボタンの操作は不要です。

## 配信と再接続

- Node版はWebSocketへ保存確定後に通知します。別のNodeプロセスが同じDBへ書いた場合も検知するため、接続中のワークスペースの軽い更新番号を1秒間隔で確認します。本文全体をこの間隔で読み直す方式ではありません。
- Cloudflare版は既存の `ROOMS` バインディングを使います。ページ共同編集とは別のワークスペース用Durable Objectで接続をまとめ、休止中も接続情報を保持します。新しいキーや接続情報の手入力は不要です。
- ワークスペースの変更通知にはページ名、本文、行の値、他人のIDを含めません。受信した画面は、現在のCookieセッション、アカウント、ワークスペース所属と参照元の閲覧権限で再取得します。ワークスペースから削除された接続には失効を通知して切断します。
- ページ本文の接続はYjsの差分をWebSocketで直接送り、確認応答と同じ認可済み接続への状態配信で合流します。送信前の本文全体の取得は省きます。接続断では未確定のYjs差分を保持し、再接続後に同じ識別子の差分を再送しても文章を重複挿入しません。通常のDBプロパティなどのCAS書き込みは、結果不明のまま自動再送しません。
- WebSocketが使えない場合は、接続を再試行しながら2秒間隔の認証付き更新確認に切り替わります。オフラインと非表示中の不要な取得を抑え、復帰時に再確認します。

常時接続はネットワーク接続中の自動同期です。オフライン中の他端末への反映や、あらゆる回線・データ量で1秒以内という保証はありません。

## 編集中の保護

日本語変換、未保存の入力、複数ブロックの文字選択、ドラッグ、サイズ変更、編集中のプロパティやダイアログを優先し、安全に適用できるタイミングで画面を更新します。本文の構造が同じ場合は既存の編集欄を更新し、本文内DBや詳細パネルを作り直しません。構造変更が必要な場合も、DBの月、選択行、スクロール位置を引き継ぎます。

本文の文字・書式・表・ブロックの構造と配置先ごとのDB設定はYjsで合流します。自分のUndo／Redoは他の端末や参加者の入力を取り消しません。DBの行・プロパティ・共有設定などは既存の認可付きCAS APIとワークスペースのWebSocketで反映します。競合や結果が不明な保存を黙って上書き・再試行しません。

リンクやメンションの参照先は、共有CRDTのバイト列へ含めず、権限付きの別の情報として保存します。各応答で現在の参照先の閲覧権限・メンバーの世代を確認し、閲覧できない参照先は利用不可の表示へ置き換えます。新規参照の登録とYjs更新は同じCASで保存します。

## 表示待ちを減らす仕組み

初回表示はアカウント、ページ一覧、本文、行のプロパティ、担当者、本文内DBの初期表示を同じ認可済みスナップショットから取得します。リンク済みビューの参照元や各行の権限も、その取得の中で確認します。初期表示の埋め込みは最大8か所・約1MBに制限し、それを超えた表示は個別に取得します。

Next.jsの起動準備と並行して、現在のページと公開されている表示設定の初期読み取りを始めます。正常時の起動用APIは1回にまとめ、ログイン方法の確認は認証できなかった場合に行います。結果は現在のURLに限って一度だけ画面へ渡し、通常の検証を適用します。別のページやアカウントの認可結果には使い回しません。使われなかった結果は10秒で破棄し、画面の終了時には取得を中断します。本文をブラウザーの永続保存領域へ追加しません。

DBの担当者情報や保存済みビューを表示するための連続した認証通信を省きます。同じ画面からの同時読み取りはまとめますが、完了した応答を認可結果として使い回しません。保存や通知で読み取りの世代を切り替え、キャンセルは呼び出し元ごとに扱います。

Cloudflareの公開HTML・JavaScript・CSSは、リクエストのたびにDBの初期設定を開かずにStatic Assetsから配信します。アカウントAPI、添付の取得、初期設定、復旧状態の検査は認証・認可の経路を維持します。

本文と詳細パネルのCSSはNext.jsでコンパイルし、スタイルの読み込みの後に別のCSSを取りに行く連鎖をなくします。日本語・英語の基本辞書は内容に応じたハッシュ付きコードにまとめます。翻訳元は従来のGitHub上の辞書を使い、キーと置換文字の検査、追加言語の取得、英語・日本語へのフォールバックも継続します。

復旧中の処理を止める検査は、その都度現在の状態を1回のSQLで確認します。旧構成で表がまだ存在しない場合だけ構造を追加確認し、壊れた復旧情報やDBの障害を正常扱いにはしません。DBの行を表示する計算では、1回の読み取りの中だけで参照索引を共有します。

## 内部の読み取り経路

これらはCookieセッションを使う画面用APIです。外部連携には[連携の案内](integrations.md)にある公開APIを使ってください。応答はすべて `no-store` です。

| 経路 | 用途 |
| --- | --- |
| `GET /api/content/workspaces/{workspaceId}/bootstrap?page={pageId}` | アカウント・一覧・ページ・初期DBを一括取得。`page` 省略時はホーム用。`view` で保存済みビューを指定可能 |
| 同経路の `section=comments` | コメント画面用の本文・コメント・担当者・受信トレイを一括取得 |
| 同経路の `section=backlinks&page={pageId}` | バックリンク画面用の参照元だけを取得 |
| 同経路の `section=attachments&page={pageId}` | 添付管理用のページ・自分のアップロード予約・保存先の有効状態を同じ更新番号で取得。本文編集権限が必要 |
| `GET /api/content/workspaces/{workspaceId}/pages/{pageId}?context=1` | ページとプロパティ・参照元の初期表示を取得。`directory=1` で一覧も同じ更新番号に揃える |
| `GET /api/content/workspaces/{workspaceId}/changes` | 所属を再確認して更新番号とメンバー情報のダイジェストだけを取得 |
| `GET /api/content/workspaces/{workspaceId}/changes/ws` | 同一OriginのWebSocket接続。クエリは不可。`ready`・`changed`・`pong`・`denied` の内容を含まない通知 |

既知のアカウントでの読み取りは `X-Yumunio-Expected-Account` を照合します。初回の `bootstrap` はセッションからアカウントを決め、応答にそのIDを返します。表示先ページの閲覧だけで、参照元DBや非公開の行が読めるようになることはありません。

## 検証

`apps/server/test/content-stream.test.mjs` と `apps/worker/integration/content-stream.mjs` は、実際のWebSocketとSQLite／workerd・D1・Durable Objectsで、別アカウントへの本文・DB・権限の変更、再接続、所属解除を確認します。通知の受信にブラウザー側のポーリングは使いません。

`apps/web/test/content-stream.test.js` は再接続、失効、WebSocketが使えない場合の更新確認を検証します。本文のDOM維持、IME中の保護、独立したUndo／Redo、DBの選択・スクロールの継続は、それぞれの編集・表示テストで確認します。計測はAPIの通信時間、画面の描画時間、サーバー内の計算時間を分け、回線・件数・コールド／ウォーム状態を併記してください。

ページ本文の直接配信は `packages/identity/test/fixtures/realtime-room-flow.js` で、同じアカウントの別接続・同時入力・再接続・ACK消失・権限失効をNodeとworkerdの双方で確認します。ページ共同編集には、既存のクライアント数・本文量・操作履歴の上限があります。ページを9枚以上開いたことによって停止する固定上限は設けません。
