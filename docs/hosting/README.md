# ホスティングの入口

| 方法 | 必要なもの | データの保存先 | 最初の設定 |
| --- | --- | --- | --- |
| [Docker](docker.md) | Docker・Compose 2.24以上。公開する場合はドメインとサーバー | 標準はSQLiteとローカル添付。Dockerボリュームで保持 | 起動ログのリンクからWeb画面で作成 |
| [Cloudflare Workers](cloudflare.md) | Cloudflare・GitHubまたはGitLabのアカウント、R2の有効化 | D1と非公開R2 | デプロイログのリンクからWeb画面で作成 |
| [ローカルで操作を試す](../../README.md#ローカルで試す) | Node.js 24.16.0以上・npm | ブラウザー内 | アカウントなし。共有ワークスペースとは別の保存領域 |

Webセットアップでは名前・メールアドレス・パスワードとワークスペース名を決めます。内部の認証情報を自分で生成・入力する必要はありません。新規登録は最初は閉じており、メールや外部ログインは導入後に設定できます。

公開する場合は、最初の設定前に使うURLを決めてください。添付、DB、内部の認証情報を含む保存領域は更新時も保持します。[更新とバックアップ](maintenance.md)、[困ったとき](troubleshooting.md)、[メールの設定](../mail-setup.md)も参照してください。

公開用Dockerイメージ・導入ZIPの取得状況は[メンテナー向けの公開手順](../maintainers/releasing.md)で確認します。配布前の開発版は、[ソースからのビルド](docker.md#ソースからビルドする)で動かせます。
