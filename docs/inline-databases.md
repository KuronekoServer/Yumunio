# 本文内のデータベースと右側の詳細編集

プロジェクトの説明文の下など、本文の任意の位置にデータベースを置けます。
空行の `/` または `+` から「データベースを挿入」を選び、新規作成か既存のデータベースを選択してください。
既存のデータベースを選ぶと、元のデータを参照する別の表示になります。行の複製は行いません。

DB上部の「表・かんばん・カレンダー・タイムライン」で、同じ行を別の形式に切り替えられます。
切り替えてもフィルター、並び順、表示する列を引き継ぎ、戻ったときの一覧内のスクロール位置と選択行も保持します。
編集できるページでは、この場所の表示形式を自動保存します。閲覧のみ、または共同編集中の切り替えは自分の画面だけに適用されます。
右側の詳細を編集中に保存する表示形式を変える場合は、詳細の保存と終了を確認してから切り替えます。
「表示設定」で、その他の表示方法、フィルター、並び順、表示する列を指定できます。
設定は本文内のブロックごとに保存され、同じデータベースを他のページや別の位置に置いても独立しています。
元の保存済みビューを変更しません。列や型の追加、共有範囲の変更は「参照元のプロパティ・共有を管理」から行います。

カレンダーは「表示設定」で指定した日付プロパティに沿って配置します。初回は参照元の同じ形式の保存ビューを優先し、なければ最初の日付列を選びます。
「前の月」「次の月」、月の入力欄、「今月」で表示月を移動できます。日付未設定の項目はカレンダーの下に残ります。
タイムラインは開始日から終了日までを横方向に表示し、月をまたぐ期間は表示月に収めます。
終了が未設定、または日付列が1つの場合は1日分として表示します。期間のバーからも行の詳細を開けます。
日付列のない既存DBでは、参照元へ日付プロパティを追加してから利用してください。新規の課題DBには「期限」を用意します。
「表・かんばん」などを切り替えても行を複製しません。日付やステータスの変更は、参照元とすべての配置先へ反映されます。

参照元DBの通常ページでは、保存済みビューの名前を選んで切り替えます。
まだない表示は「+ カレンダー」「+ タイムライン」などから追加できます。参照元の管理権限が必要です。
この操作は共有の保存済みビューを1件追加するため、本文内のブロックで表示形式を変える操作とは別です。
既存の行・本文・共有範囲は変更しません。作成結果が確認できない場合は自動再送せず、表示を更新して確認します。

DBの「…」から、この場所のタイトル・アイコン・タイトルの表示・一覧の最大の高さも指定できます。複数のDBを横に並べ、列幅をドラッグで変える操作は[サイズとレイアウト](block-layout.md)を参照してください。

行の名前やカードを選択すると、一覧を残して右側に詳細が開きます。
通常ページと同じ本文エディター、プロパティ、共同編集を利用できます。
「閉じる」または「全画面で開く」は、本文とプロパティの保存を確認してから実行します。
入力の検証や通信に失敗した場合はパネルを残し、未保存の内容を保持します。
閉じても一覧のフィルター、列、選択行、一覧内のスクロール位置を保持します。
詳細は右から200msで開閉します。閉じる際は保存の確認後に動き始め、一覧の元の操作位置へフォーカスを戻します。
閉じている間に別の操作へ移った場合は、そのフォーカスを優先します。
OSの「動きを減らす」が有効な場合は移動と待ち時間を省略します。
スマートフォンでは詳細が画面全体に広がり、「閉じる」で一覧に戻れます。
読み込みが初期の空白文書で止まった場合は一度だけ再試行します。読み込まれた編集画面は再読み込みしません。
読み込めない場合は状態を表示し、「全画面で開く」から通常ページに移れます。

同じブラウザーのページ間では変更通知を受けて一覧を取得し直します。
他のブラウザーからの変更と権限の変更は、表示中に約10秒間隔でも確認します。
一覧の再取得では周囲の本文エディターを作り直しません。

## 共有と権限

表示先ページを共有するだけでは、参照元のデータベースやその行を共有したことにはなりません。
一覧の取得は参照元の閲覧権限を毎回確認し、閲覧できる行と参照先だけを返します。
権限がない場合はデータベースの内容を表示できない旨を示します。
新規のデータベースも初期状態では作成者用です。必要な人への共有は参照元で設定してください。
参照元のアクセスを失った場合は表示済みの一覧を消し、対応する詳細パネルも閉じます。

本文に保存するのはデータベースのIDと表示設定です。行のデータや添付のバイト列を埋め込みません。
公開ページの静的スナップショットには本文内DBを展開しません。

## APIとホスト

`POST /api/content/workspaces/{workspaceId}/collections/{collectionId}/query` に `{ "view": ... }` を送ると、
保存済みビューと同じ型付き条件で読み取り専用の一覧を取得できます。ログインと期待するアカウントのヘッダーが必要です。
ビューやワークスペースの更新番号は変更せず、参照元と各行の現在の権限を適用します。
Node.jsとCloudflare Workersは同じ処理を使用します。

右側のエディターは `/workspace-detail?...&detail=1` の同一オリジンの画面を使用します。
この画面だけCSPの `frame-ancestors 'self'` を許可し、他のオリジンからの埋め込みは許可しません。
通常のページ・セットアップ・APIの埋め込み制限は従来どおりです。
パネル間の通知は送信元ウィンドウ、オリジン、アカウント、ワークスペース、ページを照合します。

## 確認シナリオ

1. 通常ページにプロジェクトの説明文を書く。
2. その下に新規の課題DBを挿入する。
3. 課題を作成し、右側で本文と担当者・ステータスを編集する。
4. 閉じて一覧の更新と選択の保持を確認し、再度開いて本文の保存を確認する。
5. 表示設定を変え、他のページに同じDBを置いて設定が独立していることを確認する。
6. 表示先だけを共有した人には行が見えないこと、元の閲覧権限を外すと一覧が消えることを確認する。
