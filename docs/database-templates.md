# DBテンプレートと自動項目

DBの「DBテンプレート」から、本文のひな形とプロパティの初期値を一緒に登録できます。
本文内DBでは「表示設定」から参照元の管理画面へ進んでください。
「新しい課題」のひな形は、概要・再現手順・完了条件の見出しを用意します。
専用のステータス型があれば最初の状態を初期値にし、担当者なども設定できます。

担当者は「@名前」で検索し、候補を選ぶと名前のチップが追加されます。複数人を続けて追加でき、チップの「×」で外せます。↑↓とEnterで選択、空の検索欄でBackspaceを押すと最後の人を外し、Escで候補を閉じます。日本語変換中のEnterは確定操作として扱います。候補は最大20件ずつ表示するため、数百人いる場合も名前で絞り込んで選べます。

右側の詳細パネル・通常ページ・DBの新規作成・テンプレートの初期値で同じ操作を使えます。以前の1人だけの担当者もそのまま表示します。フィルターの「一致する」はその人を含む担当者、「一致しない」はその人を含まない担当者に対応します。候補は現在のページを閲覧できる確認済みメンバーに限定し、選択自体でページを共有しません。新しく追加した閲覧可能な人にだけアプリ内の担当通知を送り、順番の変更や別の人の追加で既存の通知を再送しません。

新しいレコードを作る際にテンプレートを選び、項目名と初期値を確認して作成します。
初期値を変更して作成することもできます。本文とプロパティは同じ保存処理で適用します。
作成後のページは独立し、テンプレートの変更や候補からの削除は作成済みページに影響しません。

「本文を編集」は通常のページエディターを開きます。「初期値を編集」はプロパティを変更します。
「テンプレートから外す」は新規作成の候補から外し、ひな形の本文を通常ページとして残します。
本文は通常のごみ箱・履歴・共有の仕組みで管理できます。
テンプレートの管理には参照元DBの管理権限と、テンプレート本文の編集権限が必要です。
利用時にもDBとテンプレート本文の閲覧権限、担当者・Relation・本文内参照の現在の権限を確認します。
添付は新しいページ専用のIDに変換します。ローカル/S3/R2の非公開バイト列は共有する場合があります。

追加した型は次のとおりです。

| 型 | 動作 |
| --- | --- |
| ステータス | 設定した状態を1つ選択。ボードのグループ・移動・フィルターに対応 |
| URL | HTTP/HTTPSのURL。ドメインだけの入力にはHTTPSを補完 |
| 作成日時 | レコードページの作成時に自動で記録。変更不可 |
| 更新日時 | 本文・タイトル・プロパティの保存に応じて自動で記録。変更不可 |

日時はUTCで保存し、画面ではブラウザーのタイムゾーンに合わせて表示します。
日時のフィルターと並び替えに対応します。既存のFormula・Relation・Rollupは保持します。
繰り返し作成、ボタン、自動化はこの基本テンプレートには含めません。

認証済みの同一オリジンAPIは `/collections/{collectionId}/templates` のGET/POST、
`/templates/{templateId}` のPATCH/DELETE、`/records` のPOSTに任意の `templateId` を指定できます。
各更新に現在の `expectedRevision` と期待するアカウントのヘッダーが必要です。
外部向けBearer/MCPのDB操作権限を追加するものではありません。
