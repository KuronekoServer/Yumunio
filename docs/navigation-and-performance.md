# ページ移動と表示速度

ワークスペースはサイドバーとツールバーを保ち、選んだページの本文だけを切り替えます。
同じワークスペースへの本文内リンクも同様に扱い、Ctrl/⌘クリックなどブラウザー本来の操作は維持します。
戻る・進むと、直近30ページのスクロール位置に対応しています。

Ctrl/⌘+Kで開く検索は、取得済みのページ名から候補をすぐ表示し、入力が落ち着いてから保存済み本文を検索します。
矢印キーで選択し、Enterで開き、Escで閉じます。古い検索応答は新しい入力を上書きしません。

## 起動と配信

- 既存の画面コントローラーはESモジュールとしてまとめ、共通処理を共有します。数式、共同編集、設定などは必要になってから読み込みます。
- Next.jsが生成するページにモジュールの先読みを含めます。認証、表示設定、翻訳の通信は並列で開始します。
- ページ一覧やチームスペースの読み込みが、指定されたページの表示を待たせないようにします。
- DockerのNodeホストでは公開ビルドファイルだけをBrotli/gzipで配信し、ETagで再検証します。ハッシュ付きのファイルは長期保存でき、更新後は別URLになります。
- 公開JavaScriptやCSSの取得ではアカウント用の実行環境を開きません。API、添付ファイル、セッション、初期設定の制御は従来の経路を通ります。
- Workersでは同じフロントエンドをStatic Assetsから配信します。

## 保存と閲覧権限

移動前には送信中の保存を待ち、未保存の本文を保存します。競合や保存結果が不明な場合は、入力を黙って捨てずに確認します。
読み込み要求には現在のアカウントを固定し、遅い旧ページの応答が新しい選択を上書きしないようにします。

直近の本文はメモリー内に限って最大6ページ・2MiB・30秒のプレビューを保持します。
これは読み込み中に表示するためのもので、移動ごとにサーバーへ閲覧権限を問い合わせ、応答を確認するまで編集を許可しません。
同時進行の先読みを再利用でき、先読みの同時数は2件までです。
アカウントの変更、書き込み、権限エラーでキャッシュを破棄します。本文をlocalStorageやService Workerへ追加保存しません。

## 確認方法

実ブラウザーで初期表示時の通信件数・転送量と、クリックから編集可能になるまでの時間を計測します。
短いページだけでなく、長い文書、本文内リンク、連続選択、検索、スクロール位置、保存直後の移動、共同編集からの移動を確認します。
ローカルの測定値は通信回線やデータ量が異なるホストの速度保証にはなりません。
