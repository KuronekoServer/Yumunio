# ページ階層とチームスペース

サイドバーでページの説明を見ながら、子ページを作成したり、同じ階層の順番を変えたりできます。本文のブロックの入れ子とは別の、ページ同士の階層です。

| 操作 | 方法 |
| --- | --- |
| 子ページを作る | ページの横の「＋」、または開いたページの「子ページを追加」。新しいページのタイトルをそのまま入力します |
| 子ページを見る | ページ名の左の矢印で展開・折りたたみ。親ページの本文にも、閲覧できる子ページへのリンクを表示します |
| 同じ階層で並び替える | 行をドラッグして上端・下端の線へドロップ。「…」の「上へ移動」「下へ移動」もキーボードで使えます |
| 別の親へ移す | 行の中央へドロップ、または「…」→「ページを移動」。移動先と権限の継承を確認して確定します |
| チームスペースを増やす | サイドバーの「チームスペースを追加」。名前・公開範囲・参加者の権限を設定します |

ページの深さを5段で止めず、親子関係に沿って表示します。深い階層はサイドバー内を横へスクロールできます。別の親の子ページが間に混ざることはありません。展開状態とチームスペースの折りたたみは、アカウント・ワークスペースごとにこのブラウザーへ保存します。本文はこの設定に含めません。

デスクトップではサイドバーの右端をドラッグして、幅を200〜480pxの範囲で調整できます。狭いウィンドウでは本文に360px以上を残す範囲に収め、広げ直すと選んだ幅へ戻ります。幅もアカウント・ワークスペースごとにこのブラウザーへ保存し、閉じて開き直した後やページの再読み込み後も保持します。アプリ版も同じサーバーの画面で利用できます。スマートフォンでは従来のドロワー表示です。

境界をクリックすると閉じます。境界にフォーカスすると、左右キーで8px、Shiftと左右キーで32pxずつ調整できます。Homeで最小幅、Endで最大幅、Enterで閉じます。ドラッグ中のEscや操作の中断では元の幅に戻ります。閉じた後は上部の「サイドバーを開く」へフォーカスが移ります。

同じ階層の並び順はサーバーに保存され、再読み込み後も維持されます。並び替えだけでは本文の版や共同編集ルームを変更せず、現在の入力欄も作り直しません。共同編集中の階層変更・新規子ページ作成は、現在の共同編集を終了してから行います。

子ページの作成には親ページの管理権限が必要です。新しい子ページは親の権限を引き継ぎます。階層の変更ではサーバーが循環・移動先・配下の管理権限を再確認します。チームスペースをまたぐ移動は「…」→「チームスペースへ移動」から共有範囲を確認します。非公開の親ページや、閲覧できない子ページの名前は補いません。

チームスペース64件・ページ1,000件という件数の固定上限はありません。1つのチームスペースの参加者上限は1,000人です。物理的に無限の保存を保証する意味ではなく、現在の保存形式にはワークスペース本文等の合計約8 MB、JSONの処理量、本文ブロックの総量などの保護枠があります。画像・添付の実体は別のストレージです。大きなデータを移行する前に、[運用の案内](hosting/maintenance.md)とホスト側の容量を確認してください。

内部の同一オリジンAPIでは、`PATCH /api/content/workspaces/{workspaceId}/pages/{pageId}/location`に`expectedRevision`・`parentId`・`beforeId`を送ると、同じ親の子ページを並び替えます。`beforeId`は同じ親の閲覧可能なページID、末尾へ置く場合は`null`です。`inheritPermissions`を送らないこの形式はナビゲーションだけを更新します。親を変える場合は従来の移動処理になり、必要な管理権限を確認します。Cookieセッション・現在のアカウント確認・Origin・リビジョンの検査を通り、外部向けのBearer APIの権限は広げません。
